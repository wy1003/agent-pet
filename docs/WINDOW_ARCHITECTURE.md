# 窗口模块与 Facade

每类窗口在 `desktop/windows/` 提供独立 Facade。主进程组装依赖与业务服务，通过接口调用窗口；原生 `BrowserWindow` 与 `webContents` 保存在 Facade 内部。

记事板 MCP 接入位于 `desktop/notebook/mcp/`：`notebook-tools.mjs` 定义查询、新增、修改接口和输入校验；`bridge-service.mjs` 在本机回环地址提供鉴权转发；`stdio.mjs` 通过官方 MCP SDK 向外部 AI 应用提供工具。连接文件仅保存随机端口与密钥，STDIO 客户端每次调用重新读取，应用重启不会使已复制的路径配置失效。AI 进程不持有 `NotebookStore` 实例，不直接写存档。

`codex-connection.mjs` 封装 Codex 配置读写，通过注入的配置接口、运行程序解析器及 RPC 客户端完成一键连接；仅设置窗口主框架可调用。写入前备份，通过配置版本校验避免覆盖并发修改，逐字段更新本应用连接而非替换整个 MCP 配置。界面区分配置就绪与客户端实际连接。

主进程将同一个 `NotebookStore` 注入 MCP 工具接口和窗口控制器，所有写入仍在仓库队列中串行执行。仓库保存后通知窗口 Facade，通过 `notebook:changed` 触发渲染端重读；界面保留本地草稿，以 revision 拒绝冲突保存。计划和灵感的新增来源、原始内容、修改前后快照与操作时间保存在记录中；MCP 新增请求编号随记录持久化，重试不重复创建。设置窗口主框架才可复制连接配置，外部调用不能取得应用的原生窗口。

| 模块 | 职责 |
| --- | --- |
| `window-contracts.mjs` | `WindowPort`、`TaskWindowPort`、`UsageWindowPort` 的 JSDoc 结构接口与尺寸约定 |
| `window-facade.mjs` | 公共生命周期、并发创建合并、取消显示、发送方校验与导航边界 |
| `pet-window.mjs` | 宠物透明窗口、原生事件订阅与宠物状态更新 |
| `pet-menu-window.mjs` | 宠物右键菜单的透明窗口、渲染就绪握手、失焦和关闭事件 |
| `pet-menu-controller.mjs` | 依赖 `PetMenuWindowPort`，负责菜单定位、操作分发、过期请求拒绝和空闲回收；菜单 IPC 仅允许本窗口主框架调用 |
| `task-window.mjs` | 任务浮窗、尺寸上报处理和任务数量对应的对齐方式 |
| `usage-window.mjs` | 额度浮窗、刷新与尺寸上报处理 |
| `notebook-window.mjs` | 记事板浮窗，封装创建、显示、隐藏和关闭；渲染端通过数据源接口读取计划、灵感和归档 |
| `notebook-window-controller.mjs` | 依赖 `NotebookWindowPort`，独立控制记事板常驻显示、置顶、圆球收起/展开、拖动、位置恢复及屏幕边界 |
| `settings-window.mjs` | 设置窗口与文件选择对话框的父窗口绑定 |
| `daily-report-window.mjs` | 日报窗口 |
| `speech-window.mjs` | 隐藏的语音渲染宿主 |
| `companion-window-coordinator.mjs` | 基于接口协调任务和额度浮窗的显示、焦点、位置和空闲回收，不依赖记事板 |

原生窗口工厂、服务地址、偏好读取和屏幕工作区由主进程注入；协调器只依赖结构接口。业务服务、宠物运动与动画控制通过 Facade 操作窗口，不获取原生句柄。当前公共 IPC 通道仍在主进程注册，通过 Facade 验证发送方后转发尺寸、状态与服务请求。

## 展示策略

`appearance.showPet` 控制宠物本身；`appearance.showTaskPanel` 与 `appearance.showUsageCard` 控制点击宠物时展示的浮窗，默认开启，两项关闭时点击宠物不创建浮窗。`appearance.showNotebook` 独立控制记事板当前显示及启动恢复，默认关闭。`appearance.notebookAlwaysOnTop` 默认开启，独立于其他窗口的置顶选项。偏好版本 19 保留旧的显示选择，新增 `appearance.notebookStyle`（`classic` / `glass`），默认保留原有样式。

记事板通过 `NotebookWindowPort.applyAppearance/getAppearance` 管理样式。Facade 只创建透明、无边框的原生容器，不启用 Windows Acrylic、原生圆角或区域裁剪。外观接口仅返回 `style`；页面使用 `--notebook-radius: 24px` 统一控制卡片、背景和高光的轮廓，窗口外沿保持透明。样式通过主框架校验的 `notebook:appearance` 初始读取和 `notebook:appearance-changed` 事件同步；初始异步读取不覆盖更新的事件。切换不重建窗口、移动坐标或重载页面，因此草稿保留。

收起状态通过 `NotebookWindowPort.setCollapsed/getPresentation` 独立管理；`NotebookWindowController` 将同一个窗口切换为 76×76 DIP 容器，页面显示 64px 圆球。原页面仅隐藏，不重建或重载，保留详情与草稿。圆球按快照统计未完成且未归档的计划，外部更新使用现有 `notebook:changed` 链路。拖动由注入的屏幕光标与定时器计算绝对位移，移动超过 4 DIP 后不再作为展开点击；隐藏、失焦、退出取消拖动。主进程保存 `notebookState` 的收起状态、展开坐标及圆球坐标，同时保留旧的 `notebookBounds` 展开坐标。所有展示和拖动 IPC 仅接受记事板主框架。

玻璃外观参考 [liquid-glass-react](https://github.com/rdev/liquid-glass-react/blob/master/src/index.tsx) 的背景模糊、边缘位移和清晰内容分层方式。CSS 无法直接处理其他窗口的像素，因此由 `desktop/notebook/desktop-background-source.mjs` 提供桌面背景宿主元数据：只发现 `Progman` / `WorkerW`，优先 Wallpaper Engine 所属桌面宿主，绝不回退为整屏或任意应用窗口。只读 PowerShell 辅助查询通过隐藏子进程执行，5 秒缓存合并重复请求；不改变系统设置。

背景服务由入口注入记事板 Facade。`NotebookWindowPort.getBackground` 仅在记事板可见、展开且使用玻璃样式时提供背景源，隐藏或收起后的迟到结果丢弃。收起时页面停止媒体轨道，展开时恢复。主进程以 `ownsMainFrame` 校验 `notebook:background`；原生位置变化通过接口向页面发送物理像素坐标，原生句柄不泄露给其他窗口模块。

停止媒体轨道与清除已绘制画面分开处理：收起、隐藏及采集重启保留小画布中的最后一帧，展示状态标为 `cached`，沿用 `live` 的文字和玻璃样式；首帧到达后原位更新。收起事件先于窗口缩小发送，防止小视口覆盖展开画面。切换原有样式、强制颜色模式或销毁页面清除缓存。首次展开没有画面时保持 64px 圆球并暂隐面板，待首帧就绪再显示；源不可用或 1.8 秒超时后允许备用外观，不阻塞交互。展示请求序号阻止迟到结果重新展开已收起的窗口。

`public/notebook-glass-background.js` 使用无音频媒体流读取已选桌面宿主，请求 8fps、1600×900 的采集约束（实际由采集实现决定）；只将窗口覆盖区域和模糊边距绘入两个小画布。`notebook-background-geometry.mjs` 统一处理源尺寸、负坐标和 DPI 缩放。模糊画布与 SVG 位移细边共用 24px 圆角，文字不参与滤镜。移动时立即重绘当前帧，动态壁纸更新时随帧重绘，不保存或上传截图。切回原有样式、隐藏、关闭或强制颜色模式停止轨道；采集失败回退到半透明样式，可见时每 10 秒尝试恢复。该能力显示壁纸，不显示普通应用；不同 Windows 桌面宿主及壁纸软件需分别验收。

`public/notebook-glass.js` 仅响应指针移动调整高光方向，离开、切回原有样式或开启系统“减少动态效果”时复位；高光没有常驻动画循环。

托盘“打开任务列表”和任务通知属于显式查看任务入口，可临时显示任务窗口，不修改展示偏好。设置与日报始终可按需打开；语音宿主不作为可见窗口选项。

托盘和宠物右键菜单的“打开记事板 / 隐藏记事板”保存独立显示偏好，并通知设置页同步开关。记事板 Facade 不订阅失焦收起，隐藏只影响自身并保留窗口和内存草稿；不参与宠物点击、拖动联动或任务浮窗回收。入口在 IPC、服务地址及窗口状态准备完成后才应用启动显示偏好，避免过早加载页面。初始位置和显示器变化由独立控制器通过 `WindowPort` 调整；拖动后的坐标与宠物坐标分别存入 `companion-window.json`，串行写入并在退出前等待保存。普通设置变更不重排记事板位置，也不抢焦点。

记事板的 `public/notebook-source.mjs` 提供快照、添加、编辑、完成、归档、移回、删除及灵感转计划接口。页面通过 preload 调用 `notebook:snapshot` / `notebook:command`，不访问文件系统；`desktop/notebook/notebook-controller.mjs` 由入口注入存储和窗口主框架校验能力，只接受记事板所属主框架的请求。`desktop/notebook/notebook-store.mjs` 在主进程统一处理业务校验与文件读写。窗口 Facade 保持独立，业务服务不获取原生窗口句柄。生产页面不再加载示例数据源，尚未接入微信内容同步或任务执行。

存储按计划、灵感分别使用 `notebook/plans/<UUID>.json` 与 `notebook/ideas/<UUID>.json`，目录由主进程应用管理路径决定，渲染器只能传编号及受支持的命令。应用单实例主进程是唯一写入方，仓储内用串行队列避免覆盖；编辑带记录版本以拒绝过期草稿。单文件写入临时文件、同步内容并重命名替换，成功后才更新内存快照和回复界面；更新前保留上一份有效 `.bak`。读取异常主文件时尝试从备份恢复，保留损坏原件并给出提示；未知版本或无法恢复的文件保留原件，其他健康记录仍可读取。退出等待已接收的写入完成。批量归档与移回逐项写入并返回成功及失败编号，不承诺跨文件事务。

完成状态与归档状态独立。完成动作记录不可变的完整内容快照及时间；撤销完成标记该次记录的撤销时间，重做后再次完成新增快照。主列表仅过滤归档状态，保留已完成项及原有的重要优先、写入时间倒序。归档记录只读，移回保留完成状态；归档操作生成批次编号，撤销仅匹配该批次。显式删除只接受归档计划，先清理备份和该记录的恢复副本，最后删除主文件，避免重启后从备份复活。灵感转计划使用相同 UUID 的计划文件并从关联推导转换状态，保证重复转换幂等，无需同时更新两个文件。

`notebook-deadline.mjs` 统一校验与格式化本地日期 `YYYY-MM-DD` 及可选时间 `HH:mm`，不转换为 UTC；无日期不能单独指定时间，清除日期同时清除时间，仅选日期不会补成零点。操作时间保存 ISO 时间戳并按本地时区显示。输入解析层接受整点、紧凑数字及全角输入，再归一为 `HH:mm`，存储接口仍严格校验；无效草稿与空值分别处理，避免误清空。`notebook-deadline-picker.js` 封装详情和编辑共用的可取消日历面板，通过异步结果返回日期与时间，编辑草稿仍需保存才应用；时间为单个可选文本框，提供快捷值与内联错误反馈。

记事板详情的页内编辑在渲染器中按计划 ID 保留独立草稿，标题、具体事项、截止时间与重要标记在保存时通过数据源 `updatePlan` 一次提交；收到写盘成功回复后才清除草稿，失败时保留输入并提示。取消只丢弃当前草稿，不改变原计划。返回列表不隐式提交，窗口回收或重载会清除未保存草稿。新增计划和灵感继续使用独立输入面板。

宠物浮窗协调器处理任务及额度窗口的关闭、拖动后恢复、焦点切换和隐藏后的延迟回收。记事板独立控制器使用自己的请求序号，阻止关闭或退出期间的旧显示请求重新弹窗。仅显示额度时，隐藏的任务窗口无法通过空任务自动关闭事件收起额度。
