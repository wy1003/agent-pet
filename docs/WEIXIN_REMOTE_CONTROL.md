# 微信远程指令指南

> 更新日期：2026-10-21。适用于当前 `main` 分支源码，安装包能力以对应版本发布说明为准。

Agent Pet 已支持从微信向 Codex 提交文本要求，并将执行结果返回微信。Windows 上继续桌面端持有的会话时，请求直接交给该 Codex Desktop 进程，消息和回复会出现在原会话中。

## 连接并发送第一条指令

1. 在电脑上登录 Codex，启动 Agent Pet，保持电脑联网。
2. 打开“设置 → 远程通知”，扫描微信二维码；如有数字验证码，按界面提示输入。
3. 在微信向 Agent Pet 发送一条绑定消息，等待电脑显示“微信已连接”。
4. 开启“指令操作”。它默认关闭，与“发送远程通知”相互独立。开启后可以访问 Agent Pet 已识别的本机项目和会话，不再逐项目配置白名单。
5. 发送 `/sessions`，找到要继续的会话编号。
6. 发送 `/S0001 只回复收到`，将 `S0001` 替换为查询得到的编号。先收到“已接收”，完成后收到结果；同时可以在 Codex 原会话查看消息和回复。

第一次绑定消息用于建立连接。普通消息 `收到` 不会执行任务；`/S0001 收到` 才会提交到指定会话。执行指令必须使用半角 `/`，不能直接把示例编号当作自己的会话编号。

## 支持的指令

| 指令 | 用途 |
| --- | --- |
| `/help` | 查看完整帮助 |
| `/projects` | 查看已识别项目及项目编号 |
| `/sessions` | 查看最近的会话及会话编号 |
| `/sessions P001` | 查看指定项目的会话 |
| `/S0001 请补充测试` | 在原会话继续任务 |
| `/P001 新任务：检查构建结果` | 在指定项目新建 Codex 会话 |
| `/S0001 状态` | 查询会话任务状态 |
| `/S0001 停止` | 停止 Agent Pet 正在执行的远程轮次 |
| `/S0001 重试` | 对可恢复请求先检查结果，再决定是否继续执行 |

会话编号在本机稳定保存；没有项目归属的会话显示为“普通对话”，仍可通过 `/Sxxxx` 访问。项目和会话查询不会向微信暴露本机路径或真实 Codex 会话 ID。

发送“帮助”“指令”“怎么用”或 `help` 也可获得引导。旧 `/Cxxxx` 前缀继续兼容；引用消息只辅助校验目标，正文仍需使用显式指令，路由冲突会被拒绝。同一会话的多条请求会依次执行。

一条消息只指定一个目标；旧完整编号使用紧凑写法 `/P001/S0001`，不要混写成 `/P001 /S0001`。`/Sxxxx` 后的普通要求会保留原文，包括以“新任务”“继续”开头的句子；若使用续问前缀，请用 `继续：你的要求` 或 `继续 你的要求` 分隔。

## 如何判断是否送达

| 微信反馈 | 含义与下一步 |
| --- | --- |
| 已接收 / 新任务已接收 | 仅表示进入 Agent Pet 队列，还不能据此认定已写入 Codex |
| 已完成 + 结果摘要 | 已确认任务完成，可以用通知中的 `/Sxxxx 你的要求` 继续 |
| 执行状态待确认 | 提交、结果或停止状态尚无法确认；先检查电脑端，避免重复发送 |
| Codex 连接超时 | 尚未确认写入；若原会话没有请求，再发送原指令 |
| Codex 回复超时 | 已开始执行但模型回复超时；按反馈中的重试指令处理 |
| 远程任务执行失败 | 查看原因，在电脑端处理会话占用、内核兼容或执行错误 |

“停止”仅作用于 Agent Pet 发起的活动远程轮次，不能终止直接在 Codex Desktop 中启动的其他任务，也不会撤销已完成的修改。

## 桌面端与 SDK 两种执行方式

| 场景 | 执行方式 | 电脑端显示 |
| --- | --- | --- |
| Windows 上已有 Codex Desktop 会话持有者 | 通过本机 IPC 请求该桌面进程开始轮次 | 在原会话接收实时消息与回复 |
| 本机桌面端 IPC 不存在，或确认没有会话持有者 | Codex TypeScript SDK 恢复会话 | 已打开页面可能需要重新打开 |
| `/Pxxx` 新建任务 | Codex TypeScript SDK 新建会话 | 收到真实会话 ID 后保存编号映射 |

桌面端通道适配的是 **Codex Desktop 26.1013 的本地 follower 协议**，它不是公开的稳定扩展 API。权限错误、协议不匹配或提交结果不明确时会报错，不会自动再启动 SDK 写入同一请求。新建任务和 SDK 恢复仍受 Codex 自身的会话写入锁约束。

SDK 的内核查找顺序为：显式 `codexPathOverride` / `AGENT_PET_CODEX_EXECUTABLE` → `CODEX_CLI_PATH` → Windows 本机 Desktop 内核 → 内置内核 → PATH 中的 Codex。选择本机 Desktop 内核可减少旧版本无法解析新版会话记录的问题。

## 常见问题

### 微信里有“已接收”，电脑端却没有新消息

“已接收”不是送达确认。先等待后续结果或错误提示，并检查编号是否对应目标会话。若提示状态待确认，查看原会话是否已经执行，再决定后续操作。SDK 路径可能需要重新打开会话才能看到结果。

### 微信收到回复，但 Codex 页面显示“遇到了问题”

2026-10-20 修复了一处桌面端提交格式问题：纯文本输入缺少 `text_elements: []`，触发界面的 `Cannot read properties of undefined (reading 'some')` 错误。当前实现已补齐字段并加入回归测试。

如果正在运行修复前的 Agent Pet，先更新并重启 Agent Pet。等待 Codex 中的活动任务结束，再完全退出并重新打开 Codex，清除旧进程的错误状态。这次已定位的故障没有丢失已保存的请求和回复；不需要删除会话、写入锁或数据目录。若新版本仍出现同样页面，请结合日志重新排查。

### 提示会话被占用，或无法读取新版历史

确认本机 Codex 版本和正在运行的 Agent Pet 代码。桌面端通道负责复用已有持有者；无法使用该通道时，SDK 不能强行接管另一进程的写入锁。历史不兼容时检查 SDK 实际选用的内核，必要时用 `AGENT_PET_CODEX_EXECUTABLE` 指向与本机 Desktop 兼容的可执行文件。

### 查找诊断信息

数据目录中的 `remote-control/last-execution-diagnostic.json` 记录最近一次执行的路由、阶段、会话 / 轮次 ID、内核路径或失败分类；它是单条诊断快照，不是完整执行历史，也不包含请求正文或连接凭据。

## 开发维护要点

- `desktop/codex-desktop-client.mjs`：本机 IPC 连接、消息分帧、协议版本、超时和断开处理；不宣称拥有任何会话。
- `desktop/codex-desktop-executor.mjs`：发现会话持有者、提交完整文本输入、获取轮次 ID，再通过采集器确认该轮次结果；停止时带上准确轮次 ID。
- `desktop/codex-remote-executor.mjs`：选择桌面端或 SDK 路径，包装远程用户请求，记录有限诊断。
- `desktop/codex-runtime.mjs`：选择 SDK 使用的 Codex 内核。
- `src/model.mjs`：兼容 `event_msg.item_completed` 中的 `UserMessage`，按明确的会话和轮次 ID 归并问题。
- `src/collector.mjs`：继续提问时将同一会话中已结束的提醒标记为已读，保留历史。
- `desktop/remote-control-controller.mjs`：处理指令、去重、串行队列、结果回复和不确定状态。

桌面端会在后端规范化之前读取提交内容，因此文本项必须包含 `text_elements` 数组；不能仅凭后端接受请求就认定桌面界面兼容。提交之后不得因超时或断线自动切换执行路径，否则可能重复执行。

在项目根目录运行 `npm test` 执行完整回归。测试使用本地临时数据和模拟连接，不需要绑定真实微信账号。

只检查远程指令时运行 `npm run test:commands`。`test/remote-command-audit.test.mjs` 逐条执行本页指令表，并核对表中每条指令都有执行用例。新增或修改指令时同步更新帮助、文档和测试。

## 验证范围与权限边界

2026-10-20 在 Windows 开发实例完成了真实微信 `/Sxxxx 收到` 的提交与回复验证，并在修复后确认原会话可重新打开。自动化测试覆盖桌面提交字段、断线 / 超时不重复写入、精确停止目标、SDK 回退、新版用户事件采集、通知去重和同会话自动已读。

2026-10-21 对源码 0.2.1 的 9 条公开指令完成本地自动化执行检查：帮助、项目列表、会话列表、按项目筛选、续问、新任务、状态、停止和重试。检查使用真实控制器、编号登记与队列，微信发送和 Codex 执行端使用模拟实现；同时验证混合编号拒绝、未知会话提示、错误提示可直接使用、普通要求不被指令词截断，以及中文别名和旧编号兼容。这不等同于真实微信或安装包验收。

`/Pxxx` 新任务、长任务停止 / 重试、旧指令与引用兼容、断线重连、重复投递及多项目隔离仍需补充真实微信验收；安装版的端到端验证也应单独执行。

当前只接入个人微信，其他聊天渠道尚未实现。指令操作只接受已绑定账号的私聊，并经过权限检查和高风险指令拦截。执行使用受限工作目录、不申请提权；需要电脑端审批的操作应回到电脑处理。Agent Pet 不直接改写 Codex 原始 JSONL，由 Codex 保存通过桌面端或 SDK 提交的请求和结果。
